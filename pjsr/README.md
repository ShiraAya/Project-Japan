# PJSR — Project Japan Spline Roads edition

**0.1.0-alpha：真实区域原型。** 基于完整 PJR 0.1.24 源码和原始地形资源，
Minecraft 1.20.1 / Forge 47.4.20 / Java 17 / SR 1.0.15，三轴比例 0.5。

## 安装与体验

1. 将 `PJSR-0.1.0-alpha.jar` 和 `SR-1.0.15.jar` 放入客户端与服务器的 `mods`。
2. 移除普通 PJR 的 JAR：PJSR 保留 `pjr` 模组 ID，两者不可同时安装。
3. 新建世界，选择 **PJSR · 日本道路版**。开启作弊或使用服务器 OP。
4. 输入 `/pjsr visit` 到达试验路段；`/pjsr info` 查看版本、范围和署名。
5. 使用 SR 原生工具修改标线、分割或删除。自动道路为世界所有者，需要管理员权限。

本版包含高尾国道20号约 1,071 格（现实约 2.14 km）的连续试验段：
11 个来源 way，14 个有稳定 ID 的编辑单元，含 2/3/4 车道变化和両界橋。
道路随新区块生成；无游戏内下载。默认东京出生点不在试验段，需使用上述传送命令。

原 PJR 预设仍只生成原地形。旧 PJR 存档不会补铺道路。本版所有预设都要求安装 SR，
缺少 SR 或不兼容版本由 Forge 明确拒绝启动。不要直接修改已生成世界的预设或路网快照。

## 已实现

- 使用 PJR `Geo` 与纯地形采样；整段规划后按当前区块裁切，不强制加载沿线区块。
- SR 原生网格、碰撞、结构、端点和可保存道路记录；左侧通行。
- 跨编辑单元共用位置、宽度、切线和标线相位；道路附近区块避让植被。
- 原生编辑/分割/删除触发持久覆盖记录；自动生成不再覆盖该单元。
- 桥梁采用 SR 结构规划；拒绝湿地桥墩与非桥梁涉水路线；不运行微碎片 Infill。
- 固定数据快照、内容哈希、生成状态和覆盖日志；不自动升级世界道路。

## 当前边界

这是方案第17节要求的最小真实区域原型，不表示 P1 全部验收完成。
尚未实现全国/区域通用编译器、高速 IC/JCT、隧道、国道交叉路口和 PJM 路网显示。
当前筛选器明确限定高尾旧国道20号，不应直接用于全国数据。
端点是区域样本边界，不是已验证的高速出口接口。
整平填方有限制但未制作自然边坡；道路命中区块暂时整体禁用植被。
所有14个计划常驻适合此样本，不能当作全国缓存方案。
客户端视觉、驾驶体验、多人同步、光影模组和强制断电恢复仍需实机验收。
通过与未测项目见 [PROGRESS.md](PROGRESS.md)。

## 从分支构建

构建项目是仓库的 `pjsr/`，不是根目录旧 PJ 工程。

```bash
cd pjsr
python3 tools/prepare_base.py
# 将已有 SR-1.0.15.jar 放入 libs/
./gradlew build
```

`prepare_base.py` 从仓库 `downloads/PJR-0.1.24/` 固定 JAR 分片还原 1,380 个
原始地形/水文资源，并校验整包 SHA-256；无需重新下载地理数据。
首次构建需要 Forge/Minecraft/Gradle 依赖，游戏运行完全离线。
输出 `build/libs/PJSR-0.1.0-alpha.jar`；发布包不含 SR。

```bash
python3 -m unittest discover -s tools -p 'test_*.py'
./gradlew validatePjsrCore
```

`check` 执行道路核心验证和 50 MB 制品预算。原 PJR 地理审计保留独立任务，
本轮没有重新运行完整旧版地理审计，也没有改变其固定地形字节。
专用服集成验证方法见 `docs/validation.md`。
